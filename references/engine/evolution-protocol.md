# 自进化协议

> AI无法主动轮询外部世界。自进化靠"用户触发+AI自检"，不是后台守护。

---

## 一、触发方式

| 触发源 | 触发方式 | 示例 |
|--------|---------|------|
| 用户告知 | 用户提到新规/政策/平台变化 | "Amazon刚改了佣金政策" |
| 用户反馈无效 | 用户说"不对/过时/这个数错了" | "这个汇率不对，现在7.1" |
| 用户分享结果 | 用户上架/运营成功或失败 | "这个产品上架月销5000" |
| 用户主动触发 | 用户说"检查时效性"/"更新数据" | "帮我查查税率过时没" |
| AI自检发现 | AI引用数据时发现日期过旧 | 引用2024数据时主动标"需验证" |

---

## 二、自进化动作

每次交互后检查：

1. 用户说"不对/过时" → 记录到memory，标记数据类型，降低该数据置信度
2. 用户提到新规 → 验证后更新references（需用户提供来源）
3. 用户上架成功/失败 → 记录品类+平台+数据，更新品类成功率参考
4. AI引用数据时发现旧 → 主动标"需验证"，触发sop-timeliness-check
5. 同一问题被多次问到 → 考虑补充知识库

---

## 三、知识库更新规则

- 来源必须是官方/可靠（用户提供时追问来源）
- 更新时标注更新日期+来源
- 与现有知识矛盾时，以最新官方信息为准
- 不确定的标注"需验证"
- 更新后同步刷新对应文件的时效元数据

---

## 四、SOP时效巡检机制

### 元数据规范

每个数据型reference文件头部必须含：

```
> 最后更新：YYYY-MM-DD
> 最后核实：YYYY-MM-DD
> 核实周期：每季度 / 每半年 / 每年
> 下次核实：YYYY-MM-DD
```

### 状态定义

| 状态 | 定义 | 处理 |
|------|------|------|
| ok | 未到期 | 正常引用 |
| due-soon | 距核实日≤14天 | 提醒"即将到期" |
| overdue | 已过期 | 标"需验证"，触发web_search核实 |
| missing-meta | 缺元数据 | P0缺陷，必须补 |
| malformed-date | 日期非法 | P0缺陷，必须修 |

### 核实周期建议

| 数据类型 | 建议周期 | 文件 |
|---------|---------|------|
| 汇率 | 每次使用时 | profit_calculator.py内置 |
| 税率 | 每季度 | cross-border-guide.md / us-sales-tax.md |
| 平台规则 | 每季度 | platform-rules.md |
| 平台佣金 | 每季度 | pricing-analysis.md |
| 市场规模 | 每半年 | world-ecommerce.md |
| 趋势分析 | 每年 | 2026-ecommerce-trends.md |
| 品类分类 | 每年 | product-categories.md |
| 认证体系 | 每年 | cross-border-guide.md |

### 巡检执行

```bash
node scripts/sop-timeliness-check.mjs --json
```

返回各文件状态、健康度评分。健康度满分10，存在missing-meta/malformed-date直接0分。

---

## 五、AI自检触发

引用以下数据时，AI必须主动检查时效：
- 税率 → 看cross-border-guide.md核实日期
- 汇率 → 明示"示例值，需实时核实"
- 平台规则 → 看platform-rules.md核实日期
- 市场规模 → 看world-ecommerce.md核实日期
- BSR系数 → 明示"经验估算，无时效"

超期数据引用时必须标注"⚠️ 该数据最后核实于XX，可能已过时，建议web_search核实"。
